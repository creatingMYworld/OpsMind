Product

An operations console that reaches a conclusion.

Logs, metrics and cost are already in Google Cloud, on three different screens with three different time axes. OpsMind reads all three and does the joining — deterministically, so the same window always produces the same answer.

◉

Incidents, not alerts

A threshold crossing becomes an incident with a timeline, the conditions that fired, and a suspected root cause identified from which service error logs actually blame.

◈

Patterns and anomalies

Every log line clustered by template, and each series compared against its own baseline — because a fixed threshold cannot tell you what is unusual for this service.

A ranked queue, not a wall

What to do now, why it matters, the first step, and how you will know it worked. Priority is not severity: a resolved critical ranks below a firing warning.

Optional Gemini narration over an evidence bundle. Every number it emits is checked against that evidence, with a deterministic fallback so a demo cannot break.

About

Built for Cognizant's Google Cloud hackathon, Use Case 2.

A cloud-based log monitoring and visualization solution with a dashboard that tracks resource usage and suggests cost-saving actions. The application it observes — CogniKart, a storefront on Cloud Run — is deployed separately and exists only to produce honest telemetry.

✓

What we will not do

No invented savings figure. No cost presented as billed when it is modeled. No claim of machine learning where the code is arithmetic. Where a number cannot be derived honestly, the product says so instead of printing one.

⌁

How failure is demonstrated

Fault injection lives in the application, not here. A monitoring platform that can break the thing it watches is a harder thing to trust — so OpsMind has no write path at all.
